PhishGuard

PhishGuard is an email phishing detection system with a FastAPI backend, a React frontend, and local SQLite storage. It can scan emails, classify them as phishing or legitimate, store results in a database, and produce model-based explanation details.

What this project includes

  • Backend API in api.py using FastAPI, SQLAlchemy, and Uvicorn
  • Email classification logic in backend/predictor.py
  • Email fetcher via IMAP in backend/email_receiver.py
  • Explanation engine in xai/explain.py
  • SQLite database in phishing.db (created automatically)
  • React frontend in frontend/
  • Model artifacts under model/
  • Optional utilities for training and testing

Prerequisites

  • Node.js and npm installed
  • Git (optional)

Backend setup

  1. Open a terminal in the repository root.
  2. Create and activate a virtual environment:
python -m venv .venv
.\.venv\Scripts\Activate.ps1
  1. Install Python dependencies:
pip install -r requirements.txt
  1. Copy environment variables and fill in your values:
copy .env.example .env

Edit .env and set:

  • PHISHGUARD_GMAIL_EMAIL
  • PHISHGUARD_GMAIL_APP_PASSWORD
  • PHISHGUARD_PHISHING_THRESHOLD (optional)
  • PHISHGUARD_ALLOWLIST_MODE (optional)
  • PHISHGUARD_TRUSTED_SENDER_DOMAINS / PHISHGUARD_TRUSTED_SENDERS (optional)

Running the backend

Start the API server:

python api.py

This launches the FastAPI application and binds to port 8000 by default. If 8000 is busy it will try 8001, 8002, and 8003.

You can also run explicitly with Uvicorn:

uvicorn api:app --reload --host 0.0.0.0 --port 8000

Backend API endpoints

  • GET / - health check
  • GET /accounts - list configured IMAP accounts
  • POST /accounts - add a new IMAP account
  • DELETE /accounts/{email} - remove an account
  • GET /emails - list stored emails
  • POST /fetch - fetch and scan emails from configured accounts
  • POST /reclassify - reclassify all stored emails with current logic
  • GET /explain/{email_id} - get explanation for a stored email
  • GET /stats - summary statistics for scanned email data

Frontend setup

Open a separate terminal and change to the frontend/ directory:

cd frontend
npm install
npm start

The React app uses axios to communicate with the backend API. It should open in your browser at http://localhost:3000 by default.

Database and storage

  • Local database: phishing.db
  • Email records: database/db.py defines Email, User, and Account
  • SQLite tables and columns are created automatically when the app starts

Email classification behavior

The system combines multiple detection signals:

  • TF-IDF text classification
  • URL extraction and suspicious-link detection
  • sender trust and allowlist settings
  • urgency and link density heuristics
  • model ensemble of basic and enhanced classifiers if available

The backend stores each scanned email with:

  • sender
  • receiver
  • subject
  • body
  • prediction (Phishing or Legitimate)
  • risk_score
  • folder (spam or inbox)
  • explanation metadata via /explain/{email_id}

Important files

  • api.py — FastAPI application entry point
  • backend/predictor.py — email scoring and prediction logic
  • backend/email_receiver.py — Gmail IMAP fetcher and scanner
  • backend/config.py — environment-driven configuration
  • backend/policy.py — trusted sender/link helpers
  • backend/preprocess.py — text cleaning pipeline
  • xai/explain.py — explanation generator for model decisions
  • database/db.py — SQLite ORM models and DB initialization
  • frontend/ — React UI client
  • train_enhanced_model.py — optional enhanced model training pipeline
  • test_enhanced_model.py — optional model comparison tests
  • reclassify_all.py — helper to re-run classification for stored emails

Optional utilities

  • python main.py - prints a preview of CSV datasets under datasets/
  • python reclassify_all.py - reclassify stored emails after model or threshold changes
  • python test_enhanced_model.py - compare enhanced model behavior
  • python train_enhanced_model.py - retrain/experiment with enhanced model artifacts

Environment variables

Use .env.example as a template. Key settings:

  • PHISHGUARD_GMAIL_EMAIL and PHISHGUARD_GMAIL_APP_PASSWORD for Gmail IMAP access
  • PHISHGUARD_PHISHING_THRESHOLD controls the phishing decision cutoff
  • PHISHGUARD_ALLOWLIST_MODE governs trusted sender handling
  • PHISHGUARD_TRUSTED_SENDERS, PHISHGUARD_TRUSTED_SENDER_DOMAINS, PHISHGUARD_TRUSTED_LINK_DOMAINS

Running the full system

  1. Start the backend API with python api.py
  2. Start the frontend with npm start from frontend/
  3. Open the React UI and add or view configured accounts
  4. Use the frontend or POST /fetch to scan email messages
  5. Review email classifications and explanations in the UI

Notes

  • The system uses model/phishing_model.pkl and model/tfidf_vectorizer.pkl by default.
  • If enhanced model files are present, backend/predictor.py can also load model/phishing_model_enhanced.pkl and model/tfidf_vectorizer_enhanced.pkl.
  • Do not commit .env or any sensitive credentials.

Troubleshooting

  • If the backend cannot start, verify Python dependencies and .env values.
  • If the frontend cannot connect, confirm the API is running and CORS is enabled in api.py.
  • If IMAP fetch fails, ensure Gmail App Passwords are enabled and IMAP access is permitted.
